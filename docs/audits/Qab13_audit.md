# Audit report for `Qab_paper-master.zip`

**Overall conclusion:** I did not find a mathematical or computational error that invalidates the claimed finite reduction and elimination, within the scope of this audit. The main mathematical chain is coherent, and the decisive verification artifacts I reran either passed or regenerated byte-for-byte identical outputs.

That said, I would **not** call the package publication-ready as-is. There are several reproducibility and documentation problems: stale manifests, stale regeneration scripts for the large one-nonunit catalogue, unpinned optional dependencies, and C++ warning/readability issues. These do not appear to undermine the already-bundled verification results, but they would confuse an independent referee trying to reproduce everything from scratch.

## 2. Executive mathematical verdict

The proof architecture is internally consistent:

1. The paper reduces a possible common noncyclotomic factor to “package states” carrying exact degree, scale, endpoint coefficient, and local slope data.
2. The unit-coefficient branch is eliminated by a combination of modular gcd certificates and irreducibility certificates.
3. The both-nonunit branch is reduced to a small bounded computation and eliminated.
4. The large one-nonunit branch, (D \ge 16{,}584), is eliminated by exact row/pair filtering.
5. The corrected residual one-nonunit branch, (D \le 16{,}583), is eliminated by a conservative enumeration followed by eight modular gcd certificates.

The most important correction in the current paper is that the final residual one-nonunit branch uses the safe bound

[
d^3 < 64D^2,\qquad D\le 16{,}583,
]

which gives

[
d \le 2601.
]

This is correctly reflected in the current paper and in `data/qab12/one_nonunit_residual_manifest.json`. An older manifest still says the residual branch remains and incorrectly records (d \le 224); that manifest is stale.

## 3. Mathematical review

### 3.1 Unit-circle and squarefreeness arguments

The unit-circle removal argument is sound in outline. The triangle-equality step identifies possible unit-modulus roots of the trinomials as roots of unity, and the denominator removes the forced double cyclotomic roots. The remaining reciprocal-package factors are therefore off the unit circle and squarefree in the intended sense. I did not find a gap in the local use of this fact later in the proof.

### 3.2 Extraction-degree identities

The extraction-degree lemma is correct. If

[
K=\mathbb Q(\alpha^r),\quad L=\mathbb Q(\alpha^s),\quad E=\mathbb Q(\alpha),
]

with (\gcd(r,s)=1), then (\alpha) is recovered from (\alpha^r) and (\alpha^s) by a Bézout combination. Hence

[
E=KL,\qquad d=[E:\mathbb Q]\le [K:\mathbb Q][L:\mathbb Q]=e_1e_2,
]

and the tower identities

[
d=t e_1=u e_2,\qquad 1\le t\le r,\quad 1\le u\le s
]

are valid.

The code uses these identities exactly in the pair filters:

```text
d == t*e
d <= e1*e2
gcd(r,s) == 1
```

### 3.3 Reduced correspondence bound

The reduced correspondence proposition is one of the central mathematical filters. The construction

[
U_0=\frac{a}{a+b}x^b,\qquad 1-U_0=\frac{b}{a+b}x^{-a}
]

and similarly for the second package gives two curves in (\mathbb P^1\times\mathbb P^1). Their bidegrees produce the bound

[
d\le
\frac{rs(ae+bc)}
{\gcd(rb,se)\gcd(ra,sc)}.
]

The proof correctly handles the identical-package exception, and the code implements the same formula. When the unordered primitive shapes agree, the code also applies the stronger same-shape bound

[
d\le 2rs,
]

matching the paper’s warning that same unordered shape and same selected orientation should not be conflated.

I did not find a computational mismatch in this part.

### 3.4 Norm transfer and endpoint slope signatures

The norm-transfer identities

[
u_1^t=U^r,\qquad |v_1|^t=|V|^r,
]

and their second-package analogues are correctly used to force integer divisibility and slope signatures. The package-state code checks, for each coefficient prime (p),

[
\lambda=\frac{r,v_p(U)}{t}\in\mathbb Z_{>0},
]

then checks the endpoint occupancy

[
w_p=\frac{b\lambda}{\kappa},\qquad
1\le w_p\le \min{b,e},
]

and the residual congruence

[
e-w_p\equiv 0 \text{ or } -2 \pmod p.
]

The one-nonunit and residual verifiers recompute these conditions from the CSV rows rather than trusting the generator output. This is a strong positive point.

### 3.5 Two-nonunit cutoff

The paper proves that if both endpoint coefficients are nonunits, then

[
D\le 16{,}583.
]

The relevant inequality compares a lower height bound with

[
d\le 2\lfloor \log_2D\rfloor\lfloor \log_3D\rfloor.
]

The script `certify_qab12_constants.py` independently verifies the cutoff. It reported:

```text
two_nonunit_cutoff_max_D=16583
two_nonunit_degree_max=224
two_nonunit_linear_bound=D<19d
two_nonunit_endpoint_valuation_max=14
coefficient_transition_table=PASS
```

This branch is internally consistent. The (d\le224) bound belongs to the both-nonunit branch; it should not be used for the residual one-nonunit branch.

### 3.6 Coefficient trichotomy

For (D\ge16{,}584), the paper proves that at most one of (U,|V|) is nonunit and that the remaining nonunit coefficient is at most (26). For (D\ge50{,}000), this improves to (12). The constant-checking script verifies the transition table and the per-(U) caps, including:

```text
U=2:  D_cap=6816241, max_degree=143799
U=26: D_cap=16743,   max_degree=2617
```

The code’s hard-coded tables agree with the certificate output.

### 3.7 Capelli exceptional (-4K^4) branch

This is the densest part of the mathematical proof and the place I would flag for the most careful human rereading.

The paper handles Capelli’s exceptional case

[
\beta=-4\eta^4
]

by observing that (-\beta) is a square and then applying a 2-adic Newton-edge obstruction to rule out total-role and unit-endpoint packets. The only surviving possibility is a nonunit endpoint block with

[
e_1\le b,\qquad 2b\mid e_1\kappa.
]

I did not find an immediate contradiction or computational mismatch here. The later code implements the resulting endpoint-defect condition. But this part depends heavily on the correctness and applicability of the Newton-edge power obstruction and residual-splitting lemmas. I would treat this as a proof-critical local argument that deserves independent specialist checking.

### 3.8 Unit-coefficient branch

The unit branch is divided into three cases:

| Branch                      |       Terminal data | Verification method                               |
| --------------------------- | ------------------: | ------------------------------------------------- |
| Full Kummer, (D\ge50{,}000) |     7 package pairs | 28 modular gcd certificates                       |
| Full Kummer, (D<50{,}000)   |     3 package pairs | 12 modular gcd certificates                       |
| Kummer defect               | 46 primitive shapes | 106 modular factorizations proving irreducibility |

The modular gcd criterion is appropriate: for each terminal package pair and each of four orientations, the verifier reconstructs the two raw collision trinomials over (\mathbb F_p) and checks that their gcd has degree exactly (2). Since the selected scales are coprime, this degree (2) accounts for the forced double root at (x=1), leaving no noncyclotomic common factor.

The subset-degree irreducibility certificates are also mathematically standard: if the factor-degree subset-sum sets modulo several good primes intersect only in ({0,n}), then the integer polynomial is irreducible.

I reran the direct irreducibility verifier. It verified all 46 shapes and all 106 modular factorizations.

### 3.9 Residual one-nonunit branch

The current residual branch is mathematically consistent with the corrected envelope:

[
D\le 16{,}583,\qquad |V|=1,\qquad 2\le U\le D,\qquad d\le2601.
]

The generator uses five slope-signature slots. This is enough because an integer at most (16{,}583) has at most five distinct prime factors:

[
2\cdot3\cdot5\cdot7\cdot11=2310\le16583,\qquad
2\cdot3\cdot5\cdot7\cdot11\cdot13=30030>16583.
]

The residual pair sieve leaves four state pairs, collapsing to two package pairs:

```text
U=8,  d=99:
  (3;440,1,441) vs (4;3024,1,3025)

U=32, d=123,205,285:
  (1;6560,1,6561) vs (2;1024,1,1025)
```

For these two package pairs and four orientations each, the verifier recomputes all eight modular gcds over (\mathbb F_{1009}). All have gcd degree exactly (2), so the terminal residual branch is eliminated.

## 5. Code review findings

### 5.1 Strong points

The package has several good verification-design features:

1. **Separation between generators and verifiers.**
   The verifiers recompute arithmetic row conditions rather than merely trusting stored output.

2. **Deterministic CSV artifacts.**
   The key branches sort and deduplicate records, making hash comparison meaningful.

3. **Exact integer arithmetic for filters.**
   The core filters use integer divisibility, gcd, support, degree, and congruence checks.

4. **Terminal modular certificates are independently recomputed.**
   The modular gcd verifiers reconstruct the polynomials from package data.

5. **Residual verifier is particularly strong.**
   `verify_one_nonunit_residual.py` rereads every package row, reruns the pair sieve, compares terminal CSVs exactly, and recomputes all eight modular gcds.

### 5.2 Important reproducibility problems

These should be fixed before circulation.

#### Issue 1: stale branch manifest

`data/qab12/QAB12_BRANCH_MANIFEST.json` is stale. It says:

```text
status:
eliminates_upper_unit_both_nonunit_and_one_nonunit_D_ge_16584;
small_one_nonunit_D_le_16583_remains
```

and records the residual branch with:

```text
d_max = 224
```

This contradicts the current paper and the current residual manifest, which correctly uses:

```text
D_max = 16583
d_max = 2601
status = PASS
```

This is not a mathematical flaw in the current proof, but it is a serious documentation/reproducibility flaw.

#### Issue 2: stale branch summary

`data/qab12/qab12_branch_summary.json` also contains stale text saying the residual branch remains and refers to degree (224). The current paper and residual manifest supersede this, but the file should be regenerated or removed.

#### Issue 3: broken or stale all-one-nonunit regeneration scripts

The Makefile target

```text
q12-one-nonunit-all
```

calls:

```text
code/qab12/run_all_one_nonunit_unfiltered.sh
```

That script writes to paths such as:

```text
data/one_nonunit_all_chunks
data/one_nonunit_all_packages_U*.csv
```

but the current package stores the active artifacts under:

```text
data/qab12/...
```

It also calls:

```text
python3 code/merge_package_chunks.py
```

whereas the actual file is:

```text
code/qab12/merge_package_chunks.py
```

So the advertised all-one-nonunit regeneration path appears stale in the current tree.

There is also an older `run_all_one_nonunit.sh` that points to:

```text
build/enumerate_one_nonunit_packages
```

but the Makefile builds:

```text
build/qab12_enumerate_one_nonunit_packages
```

These scripts should be corrected or removed.

#### Issue 4: stale manifest verifier path assumptions

`verify_one_nonunit_all_manifest.py` appears to assume an older `data/` layout rather than `data/qab12/`. The active verifier `verify_one_nonunit.py --data-dir data/qab12` works, but the manifest verifier is not aligned with the current tree.

### 5.3 Dependency issue

The modular and irreducibility verifiers require `python-flint`, but the package only lists it in `requirements-optional.txt` and does not pin versions or provide a lockfile/container recipe. In a clean environment, the modular checks initially fail with:

```text
ModuleNotFoundError: No module named 'flint'
```

After installing `python-flint`, the checks passed. For a proof package, this should be made more robust with pinned dependencies or a container image.

### 5.4 C++ warnings

The C++ code compiles and runs, but it emits many warnings, especially:

```text
-Wmisleading-indentation
-Wpedantic for __int128
```

The misleading-indentation warnings are mostly caused by compact one-line constructs such as:

```cpp
if(condition) continue; ++counter;
```

The semantics are usually correct because `continue` exits the loop before the counter increment, but this style is risky in verification code. I recommend adding braces throughout.

The use of `__int128` is reasonable on GCC/Clang for overflow-safe products like (d^3), but it is non-standard C++. The package should either document GCC/Clang as required or replace these checks with portable checked-multiplication helpers.

## 7. Final assessment

I would summarize the state as follows:

**Mathematically:** The reduction and elimination strategy is coherent. I found no fatal gap in the core finite-reduction chain I audited. The residual correction from (d\le224) to (d\le2601) is correctly handled in the current paper and active residual verifier.

**Computationally:** The active verification scripts passed. The both-nonunit and corrected residual one-nonunit branches regenerated exactly from source, with hashes matching the bundled data. The unit modular gcd and defect irreducibility certificates also verified.

**Reproducibility:** The package needs cleanup. In particular, stale manifests and stale regeneration scripts should be fixed before relying on this as an independent proof archive.

My bottom-line verdict is:

> The current bundled artifacts provide strong computational support for the claimed elimination, and I did not find a counterexample to the proof logic. However, the repository should be cleaned and re-manifested before publication or formal peer review, because several machine-readable status files and regeneration scripts contradict or lag behind the current proof.
